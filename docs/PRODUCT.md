# 校园 Inbox · 重构产品约定

这份约定用于实现和验收，不放到产品页面上。重构目标是网页与 Android 共用稳定的通知业务，改为清晰的 Material You 风格，并让后续同步、问答和提醒有明确的接入位置。

## 核心使用流程

1. 粘贴一条或数条原通知，为每条分别添加附件。
2. 用户点击整理后，整批只发一次模型请求；已有通知、笔记和附件不发给模型。
3. 保存成功后回到清单。先看适用对象，再看要做的事及必要步骤。
4. 勾选步骤或事项，或将与自己无关的条件任务标记为不适用。全部处理后通知进入已完成。
5. 随时记笔记、查原文或预览附件；日期明确时可加入日历。
6. 通过备份迁移全部数据，或邀请码注册后登录账号同步文字、笔记与状态；附件保存在各自设备。

## 功能保留与简化

| 功能 | 重构后的行为 |
| --- | --- |
| 批量整理 | 1–20 个输入模块，合计 4,000 字，一次提交对应一次模型调用。正文中的 `---` 在新模块协议中只是原文。 |
| 来源与附件 | 一模块对应一条结果，附件跟随自己的模块；附件不进入 AI 请求。 |
| 任务与提醒 | 保留任务、规则提醒、信息告知三种业务类型；界面合并提醒与告知到“提醒”，不额外增加“知悉”导航。 |
| 责任对象 | 条件或角色标签靠近事项标题。班长、家长或委员的工作不能变成全体同学必做；条件文字直接可见。 |
| 子步骤 | AI 从原文明示流程中提取，同一执行者、同一条件、同一目标的操作才放在一组；步骤及必要内容直接可见。 |
| 笔记 | 事项、步骤、提醒要点可分别记录，旧通知级笔记保留；笔记入口不再同时承担步骤改名、适用范围和日期编辑。 |
| 完成 | 子步骤全部完成使父事项完成，事项全部完成或不适用使通知完成；操作集中由一个业务更新函数负责。 |
| 撤销 | 完成、删除提供简短 snackbar 撤销；恢复保存原对象及进度，不重新生成 AI 内容。 |
| 搜索与排序 | 搜索标题、原文、要点和笔记；优先级与截止排序均使用同一有效截止计算。排序只有一个选择控件。 |
| 紧急事项 | 今日、3 天内、已截止使用本地时间计算，可跳到对应通知；不猜缺失的年份或发布时间。 |
| 日历 | 完整时间预填，完整日期可选全天；时间不完整由用户补齐。网页版导出 ICS；Android 打开系统日历编辑界面。 |
| 附件 | 图片、PDF、文本原地预览，其他类型下载。HTML、SVG 按文本查看，不执行用户附件内容。 |
| 备份 | 一份备份包含原文、AI 字段、笔记、完成状态和附件；导入先验证，追加不存在的通知，同一 ID 保留当前版本，不覆盖现有进度。 |
| 示例 | “载入示例通知”追加历史真实模型结果，不调用模型、不覆盖个人记录，不建立第二套演示业务。 |
| 使用帮助 | 首次简短说明，设置中可重新查看；隐私和本地保存说明只保留一处。 |
| 登录与同步 | 一次性邀请码注册用户名和密码，后续直接登录；设备会话持久保存。文字先写本地再同步，冲突由用户选择，退出不删除本地通知。 |
| Android | 接收其他应用分享的文字、系统文件选择与保存、动态配色、浅色/深色、日历确认；收到分享不会自动调用 AI。 |

移除拖动标签选择板、通知横滑完成、拟态阴影、磨砂背景和多套字体选择。手机使用系统滚动；桌面的独立面板提供常驻可拖动滚动条，使滚动位置可见，键盘也可操作。旧版不可见的独立 demoMode、附件归属弹窗和手工添加 AI 子步骤入口不带入新界面。

## 导航与界面

- 手机使用“通知 / 整理 / 设置”三个主要入口；平板、桌面使用相同入口的侧边导航或顶部导航。
- “通知”内提供“待办 / 提醒 / 已完成”状态切换，以及搜索、排序、今日/临期摘要。
- 宽度达到 960px 时，“整理”在左、通知列表在右，各自滚动；较窄屏幕使用独立页面。键盘缩短高度时不卸载面板，旋转后保留当前输入和焦点所在页面。
- 一张通知卡只突出标题、责任对象、截止和行动。原文、背景、材料放在明确的“详情”按钮后。
- 新增、删除、snackbar 和展开统一使用短过渡；只给 opacity、transform 做轻量过渡，不在动画尾端切换布局尺寸。减少动效设置下去除位移。
- 文字正文至少 16px，主要触控区域至少 48px。重要区别同时用文字和图形表达，不能只依赖颜色；正文不与笔记按钮争用窄列，子步骤的说明使用完整宽度。
- 轻度 Markdown 重点由模型直接输出，客户端渲染加粗、列表与安全链接，不执行 HTML 或加载 Markdown 图片。日历与系统提醒将轻度强调转成普通文字。

## 推荐架构

保持一个应用和一个模块化后端，不引入微服务或复杂分布式框架。

```text
src/app        组装页面、主题与应用状态
src/features   通知、整理、附件、笔记与设置界面
src/domain     通知模型、完成规则、时间与优先级
src/infrastructure 本地 repository、附件、备份迁移、AI与登录/同步客户端
src/platform   浏览器下载/ICS 与 Android 分享/文件/日历适配器
server         AI/用量、登录、同步模块，共用一个 Node 24 服务
mobile/android Android 宿主，仅承载系统能力和签名构建
```

具体目录可随实现精简。原则是业务规则只写一份，页面不直接拼写 LocalStorage 字段，原生桥不查询 DOM 的 loading 属性来判断业务状态。每个 Notice、Task、Step、Reminder 都有稳定本地 ID。UI 调用领域操作，repository 完成一次持久化更新后再通知界面；界面不同时保存三套可互相矛盾的完成状态。

AI 外部输入、备份导入、原生桥、密钥和付费限额处保留边界校验；普通内部函数依赖类型和集中规则，不在每一层重复整份校验。AI 结果与用户的笔记、时间补充、完成状态分开存，避免之后编辑或同步误改模型原字段。

## 旧数据与发布注意事项

### 浏览器迁移

- 旧通知在 LocalStorage 的 `campus-inbox:notices:v1`。
- 旧附件在 IndexedDB `campus-inbox-files`，对象仓库名为 `files`。数据含 `id/name/type/size/blob`。
- 旧输入草稿的主键为 `campus-inbox:compose:v2`，旧单条键为 `campus-inbox:draft:v1`；草稿中的 fileCount 不等于可恢复文件二进制。
- 旧笔记草稿和待保存 AI 结果在 SessionStorage。新版将可读取的结果与未保存编辑保留到本机，结果可免费重存；未确认的笔记提供查看和文字导出，不自动覆盖已有笔记。
- 现有备份是 `{app:'campus-inbox', version:4, notices, attachments}`，附件数据为 base64；兼容版本 1–4。
- 原有 task/reminder 没有稳定 ID，迁移一次生成并持久保存；已有 step ID 保留。不要每次打开随机重新编号。
- 只有迁移事务成功后才写迁移完成标记。保留旧数据作为回滚来源，避免第二次打开重复导入。
- 维持 `https://kemou2333.github.io/campus-inbox/`。不同域名无法直接读取旧浏览器数据；相同域名路径可以迁移，不代表跨浏览器同步。

### Android 升级

- 保持 applicationId `io.github.kemou2333.campusinbox`、原固定签名，提高 versionCode（旧版为 1）。不要要求卸载再安装，否则本地数据消失。
- 内置 origin 仍为 `https://appassets.androidplatform.net`，入口 `/assets/web/index.html`。现有原生策略精确检查入口，改路由时必须同步测试桥，建议使用 hash 路由。
- 固定签名仅放私密配置与 CI Secrets，不进入代码、安装包或发布日志。
- 日历返回 `opened/saved:false` 只是打开编辑界面；不能提示“日程已添加”。取消系统保存不显示文件保存成功。
- 模拟原生桥与构建成功不等于真机测试，需要明确标示系统日历、文件选择器、键盘和升级测试的实际范围。

### CI 与后端

- 当前 Pages 直接发布 `dist/`，重构后要先安装锁定依赖、免费测试、构建，再上传成品。
- APK 需使用同一份构建出的网页成品，并保持固定签名；安卓宿主不再叠加另一份厚主题 CSS。
- 新版受限后端发布器接收 9 个明确运行文件；第一次发布前必须单独更新宿主安装器清单与 Node 24 运行时，否则 CI 部署会被拒绝。
- 新版需要登录才能调用收费 AI；不再沿用旧公开匿名整理方式。免费示例仍可直接载入，客户端通过明确登录提示处理 401。
- 不把网页和 API 回滚绑定成破坏性覆盖。v4 模型结果仍兼容，但新版需要邀请账号；旧 APK 需覆盖升级到 2.0 才能登录并继续 AI 整理，旧通知和附件保留。

## 文字云同步

2 核 2 GB 服务器适合个人或小规模文本通知同步的初始方案，容量仍取决于同时使用人数和附件大小。模型计算在 DeepSeek，不在该服务器上。同步的主要成本是附件磁盘、带宽与备份；现有 3 Mbps 带宽下不宜默认把大量大附件自动上传。

本轮用户已经批准真实同步，采用单个服务配 Node 24 内置 SQLite；登录、邀请与会话在 `auth.sqlite`，通知、状态、笔记和删除记录在 `sync.sqlite`。不需要单独维护 MySQL/Redis。附件本轮不上传，备份仍可包含本地附件。

一次性邀请码注册用户名和密码，账号具有稳定 UUID 与独立同步空间，每设备会话单独退出。按 IP 限频控制尝试次数，不作为私密身份。服务器只保存邀请码、会话与密码的哈希；没有公开创建同步空间的接口。付费 AI 同时受账号、IP 与全站每日限额控制。保持增量记录、修订号及删除标记的简单协议，不引入 CRDT 或微服务。

离线更新先进本地，网络恢复后同步。不同设备同时编辑相同笔记时用修订号检测，保留两份冲突内容供选择；不能静默用旧设备覆盖新笔记。服务器短暂失联不妨碍查看和操作本机通知。

登录与同步可用独立临时数据库、假模型免费联测：两个设备登录同一账号看到相同文字、状态和笔记；不同账号隔离；同一卡冲突不覆盖；删除记录阻止旧设备复活内容；退出后不能同步或调用缓存 AI，另一设备仍能使用。超过 1,000 条或 5 MiB 的账号仍保留本地数据，并提示云容量限制。

## 12 项免费验收场景

| 编号 | 操作 | 必须得到的结果 |
| --- | --- | --- |
| 1 | 两个模块放不同原文，各放一个附件，Mock 返回两卡。 | 一次 POST，顺序和原文关联正确，附件只挂自己的卡；请求无附件、笔记和历史列表。 |
| 2 | 输入超 4,000 字、20 条、空白正文但有附件，或快速连点整理。 | 不合法输入零模型请求；合法连点至多一次；错误贴在输入区，不丢草稿。 |
| 3 | 使用家长短信、学生三步请假、不能返校才请假、负责人办理的固定结果。 | 对象及条件直接可见；角色工作不混入学生步骤；只有同一目标的连续操作是子步骤。 |
| 4 | 勾两个步骤、写步骤笔记，勾最后一步，再撤销并恢复。 | 父子状态和通知列表一致；笔记/步骤 ID 保留；全部不适用也能结束通知，撤销恢复原进度。 |
| 5 | 在事项、步骤、提醒分别写笔记，刷新、搜索、导出再导入。 | 内容保留在对应位置，无错位；旧通知级笔记仍可查看。 |
| 6 | 设置个人截止；测试精确日期、日期无钟点、缺年份、今天内、24:00。 | 排序与临期使用同一有效截止；无凭据不补年份/发布时间；全天候选不伪造 23:59。 |
| 7 | 删除后撤销、载入示例两次；示例载入前保留个人草稿与已完成进度。 | 撤销只恢复指定数据；示例不调用模型且不重复，个人数据和输入不被覆盖。 |
| 8 | 添加 PNG、PDF、HTML 文本附件，预览并备份；故意让附件写入或导入事务失败。 | 格式安全预览，HTML 不执行；失败保留旧数据和原文件，AI 已付费结果可免费重存/导出。 |
| 9 | 用旧 v4 记录和附件库首次进入新版，重复刷新；再用旧备份恢复。 | 数据只迁移一次，状态/原文/笔记/附件与原有 ID 保留；旧副本可回滚。 |
| 10 | 两标签页改不同笔记或删除前序步骤；模拟 429、428、超时及离线。 | 不覆写对方编辑；验证不额外产生模型调用；错误不自动重试付费；离线仍可查看。 |
| 11 | 320/390/768/1440 宽度，短桌面、键盘弹起、减少动效、连开闭详情。 | 无横向溢出或被遮住的提交按钮；焦点正常，动画末端无跳动；滚动不会触发完成。 |
| 12 | 模拟 Android 分享时正在整理、取消另存为、打开系统日历；构建签名 APK。 | 分享排队且不自动 AI；取消不报成功；日历只提示用户确认；同包名同签名高版本可升级。 |

这些场景不调用收费模型。真实 AI 质量另用小批原文一次普通提交评估，记录原始响应和自动校验结果；不能手写结果后声称来自 AI，也不能把少量样本通过称为所有通知无误。
