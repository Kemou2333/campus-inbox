# 公开试用与验证方案

核验日期：2026-10-07。本文记录代码能力与后续计划；生产是否已经更新，以发布验收为准。

## 本轮：自托管数字验证码

采用本服务器生成的 **4 位数字 PNG 图片**，不需要第三方账号、SDK、验证码套餐或外部网络访问。移动端直接输入数字即可，不做很扭曲的识别题。

- 默认 `CAPTCHA_MODE=image`。短时间第 3 次及以后、未命中缓存的整理会要求验证码；平时查看、写笔记、勾选、载入示例和同步不要求验证码。
- 单张验证码 120 秒有效，最多 5 次答案尝试。输错可以继续填写同一张图片，不重新申请图片，也不重复计一次三分钟限频入口。
- PNG 只含像素和标准图片块，没有明文答案、SVG text 或答案元数据。服务器挑战表只保留加盐答案哈希、期限及尝试次数，不保存明文数字或写日志。
- 签名上下文绑定账号、网络、来源、原始输入哈希和期限。正确后同步消费一次，再允许一次模型调用；两个同时提交的正确答案不能重复调用模型。
- 错误、过期、错误账号或被修改的上下文都不会调用模型。前端只对明确的 `CAPTCHA_INCORRECT` 且仍有尝试次数的结果重开输入框，不重试任何模型失败、5xx 或其他错误。
- 用户取消后不继续补交；输入框的回调收到 AbortSignal。正文在整个验证过程保持相同，只增加验证答案。
- `CAPTCHA_MODE=pow` 显式保留旧 PoW 兼容模式。新网页可处理两种方式；旧 APK 不支持图片验证码，应更新安装包或用新版网页，不能自动跳过验证。

简单图片验证码能增加随意脚本的成本，但不能保证抵抗 OCR 或批量人工。费用的最后边界仍是下面的账户、网络与全站额度；不把任何验证码当作“绝对防滥用”。

## 当前账号与费用边界

网页和示例可以公开查看。真实 AI 整理、云同步需要有效的邀请码账号会话；公开访问不等于必须开放任意注册。

- 一次性 8 位邀请码只能由私有维护端生成，没有公开领取接口。注册后用用户名和密码登录，设备会话归属同一个稳定账号。
- 默认每网络最多整理 5 次/3 分钟，账号和网络各 10 次/天，全站 30 次/天。一批新通知是一项整理请求；不是按输出待办数量计费。
- 付费调用失败仍计入次数。相同新内容 15 分钟内命中缓存不再次调用模型。每天按北京时间重置，额度落盘，服务重启不清零。
- 注册尝试与登录每网络每分钟各限 5 次；登录也按用户名限 5 次/分钟。猜错邀请码、密码错误不刷新额度。每网络成功注册最多 5 个/天，总账户上限 500。
- CORS 只约束浏览器，脚本可以自行设置 Origin；授权必须依靠服务器会话。后端默认监听回环地址，Nginx 覆盖真实 IP，不直接相信互联网客户端给出的 IP 头。

这些是代码默认值。部署环境可以调整日额度，本次审查没有读取生产私密配置。

## 前后端接口

服务端在付费调用前返回 `428 VERIFICATION_REQUIRED`，图片 challenge 为：

```ts
{ type: 'image', image: 'data:image/png;base64,...', token: '签名上下文', expires: 0 }
```

前端 `AnalyzeOptions.onHumanVerification(request, signal)` 显示图片与数字输入框，返回 4 位数字字符串。可选的 `request.error` 是上次输错的提示。再通过 `X-Campus-Proof` 提交 `{token,answer}`；不改变通知原文，也不把账号密码加入正文。

正确答案通过后才可能调用模型。错误答案返回 `400 CAPTCHA_INCORRECT` 和 `remainingAttempts`；只允许同上下文最多 5 次答案提交。其他错误不自动重试。验证码源码是 `server/image-captcha.mjs`，只使用 Node 内置 crypto/zlib。部署归档、受限安装器、Docker 与启动测试已同时加入这个运行文件。

测试全部使用本地验证码和模型模拟响应，没有验证码平台请求，也没有付费 AI 调用。覆盖 PNG 格式、答案哈希、5 次猜测、时间、身份/原文/网络绑定、并发重放、旧 PoW、取消、限额保持和输错继续填写。

## 以后如需更高级验证

使用者通常无需登录验证码平台；开发者接外部服务一般需要注册平台账号并创建应用。当前自托管方式不需要这个过程。

| 方案 | 使用者 | 开发者及费用 | 当前选择 |
| --- | --- | --- | --- |
| 自托管 4 位数字 PNG | 不登录第三方平台 | 不注册额外账号，不购买验证码服务 | 本轮采用 |
| Cloudflare Turnstile | 无需 Cloudflare 账号 | 需要开发者 Cloudflare 账号；免费方案不限挑战次数，企业功能联系销售 | 若以后扩大公开试用再考虑 |
| 腾讯云验证码 | 无需腾讯云账号 | 需要腾讯云账号；当前 2 万次/7 天测试包，正式使用付费 | 将来按需要选择 |
| PoW | 无平台账号 | 免费本地计算，只是增加脚本成本，不能识别人类 | 仅显式旧版兼容 |

Turnstile 可以单独用，不要求 Worker 或改网站托管；免费方案最多 20 个 widget、每个 10 个 hostname。[官方方案](https://developers.cloudflare.com/turnstile/plans/)、[账号与接入要求](https://developers.cloudflare.com/turnstile/get-started/)。腾讯云当前试用与正式价格见[购买指南](https://cloud.tencent.com/document/product/1110/95040)。没有创建这些平台账号或付费资源，本轮也未保留 Turnstile 的接入代码。

## 邮箱、QQ、微信：后续公开注册

评委可以先直接看示例，获得邀请码后再注册整理。无需为了公开链接立即接完整身份平台。

若扩大公开注册，优先考虑“邮箱验证 + 密码登录”。验证只用于首次注册、绑定邮箱和重置密码；正常登录不每次发邮件。

- 邮箱验证证明用户能收信，不证明是唯一自然人。QQ、163、126、Gmail 等后缀限制不能杜绝批量账号；配额、注册限速和验证码仍应保留。
- 正规发信服务需要开发者账号与可管理 DNS 的发信域名。当前 github.io 地址不提供 GitHub 所有的 DNS 权限，不能用它自行配置发信 SPF/DKIM；可以另用自有发信域名，网页仍在 github.io。
- 腾讯云官方要求发信域名管理权限与域名验证，参见[发信域名](https://cloud.tencent.com/document/product/1288/55191)、[发信身份验证](https://cloud.tencent.com/document/faq/1288/60652)。这轮不创建发信付费资源。
- 将来的邮箱验证码应短时有效、哈希保存、单次使用、限制发送和猜测次数；发送接口不泄露某邮箱是否注册，不无限发信。
- QQ 登录要注册开发者、创建应用并获得接口权限，不能直接拿个人 QQ 当网站的公开接口。[成为开发者](https://wiki.connect.qq.com/%E6%88%90%E4%B8%BA%E5%BC%80%E5%8F%91%E8%80%85)、[创建应用](https://wiki.connect.qq.com/__trashed-2)。
- QQ 网站通常需要备案信息；官方同时给海外网站提供国际域名邮件申请途径。不能承诺 github.io 直接开通，也不能断言所有海外网站都不能申请。[审核规范](https://wiki.connect.qq.com/%E7%BD%91%E7%AB%99%E5%AE%A1%E6%A0%B8%E8%A7%84%E8%8C%83)、[海外网站 FAQ](https://wiki.connect.qq.com/%E5%B8%B8%E8%A7%84%E9%97%AE%E9%A2%98-20170322)。
- 微信需公众/开放平台开发者账号与 AppID、AppSecret。腾讯 CloudBase 官方说明参见[微信授权登录](https://docs.cloudbase.net/authentication/method/wechat-login)。本次未取得微信开放平台直接文档正文，未将“个人一定能开通”或某认证费写成核实事实；开通前以当前官方申请页为准。

## 尚需独立完成的账号功能

1. 当前无密码恢复与全设备注销入口；未来邮箱验证后补恢复，不能保存明文密码或提供绕过身份的找回方式。
2. 邀请码目前没有过期/撤销机制；扩大分发前，可加 expiresAt/revoked 并兼容旧码，维护端控制撤销。
3. 同校共享 IP 可能提前触发网络上限；多人试用时按实测提高网络额度，同时保留账号及全站费用上限。
4. 次数上限不是精确人民币预算。模型价格或配置变更会改变单次成本；扩大试用前可按提供商真实用量补 token/金额预算。

本轮保持邀请码注册，不开启匿名整理或自行启用 QQ/微信/邮件登录，不改变邮箱白名单。
