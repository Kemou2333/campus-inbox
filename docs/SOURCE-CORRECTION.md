# 原文出处与人工修正

只在小待办标题、重要注意和已经关联的提醒主题旁展示出处图标。标题、简介、时间、对象、说明、步骤与材料不逐行放图标，提醒主题也只保留一个入口。点击后查看原文并高亮关联段，再从同一窗口进入「修正」。没有有效关联的旧记录不显示灰色按钮，也不凭相同文字自动猜位置；可从更多菜单进入完整「原文与附件」。

旧外研社示例的七个任务都有「报名截止时间之前」，原文中这个短句分别出现在演讲、短视频和“四新”初选。旧文字匹配会把七项都关联到同样三处并首先滚到演讲初选。这不是独立出处，因此已停用该匹配，不改通知原文、AI 字段、进度或笔记。

2.13 新整理只要求每个小待办标题 `tasks.N.text` 关联原文，建议选择最能支撑行动的 1–3 段；重要注意和有明确支撑的提醒主题可选关联。标题、简介、时间、地点和逐行说明不强制关联。程序校验字段确实存在、段号在当前原文范围内，位置由同一分段函数计算，不采用模型自报字符位置。旧记录的组键和最多八段关联继续兼容读取，界面仍只展示选定位置的图标。关联由 AI 选择，必须人工对照，不能把有链接当成事实正确。

人工修正保存在独立的 `corrections` 层，原文与原 AI 字段完整保留。修改立即写入本机并进入已有云同步流程，不会重新调用模型。完成状态、步骤 ID、笔记、附件和手动提醒日期保留。可逐字段改标题、简介、任务对象/条件/说明/步骤、时间地点、材料、注意与提醒；本版不增删任务或步骤结构。漏项可以补进相关说明。恢复初稿移除修正层，保留最新进度和笔记。

缺少年份的时间不会自动借用原年份。已设置的本地提醒日期优先保留；修正通知文字不能替代对提醒日期的确认。备份和云同步保留原字段、出处及修正层。旧记录没有这些可选字段仍按原方式读取。
