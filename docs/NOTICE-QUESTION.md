# 问这条通知：接口与边界

`POST /notice-question` 仅回答本次一条原文中的问题。它不读取其他通知、笔记、用户身份设置、整理结果或对话历史，也不联网抓取原文中的链接。需要已有登录会话和允许的 Origin，沿用 `Authorization: Bearer <session>`。

请求：

```json
{"sourceText":"单条通知原文","question":"本次问题","requestId":"客户端生成的 UUID"}
```

- `sourceText` 1–4000 字、`question` 1–240 字，校验后仅去除两端空白；不截断、不拆分。复制原文的隐藏排版符允许作为转义 JSON 数据发送，原通知不改写；问题中的异常控制符仍拒绝。空原文、超长原文、空问题等分别提示，未知字段拒绝。
- `requestId` 接受现有安全编号规则：16–100 个 ASCII 字符，首位字母/数字，其余字母、数字、`.`、`_`、`:`、`-`。建议用 `crypto.randomUUID()`。
- 请求体上限仍为 64,000 字节。客户端只发原文、本次问题、编号。

成功 `200`：

```json
{"answer":"报名于10月20日截止。","evidence":["报名于10月20日截止。"],"remainingQuestions":4}
```

回答最多1000字（提示词优先80–180字，多问题用短加粗标题、空行与要点分开；通常不超过240字，保留条件和不确定性）；最多2段引用，每段最多500字，总计最多1000字。程序验证引用为该原文的精确连续子串，并拒绝不在原文的链接。原文没有说明时可返回空引用。界面原文依据默认折叠，旧缓存长纯文本只按原标点分段，不重新收费或改写事实。输入在接纳前拒绝时恢复“提问”按钮，保留同一请求编号。引用存在并不等于语义已经核实；日期歧义和条件仍须保留，不推断个人资格。

模型保持既有 `AI_MODEL` 与 `low` 配置、JSON object 模式、最多180秒；问答输出预算8192 Token，包含思考，低于整理的既有上限。只有系统消息具备指令权限；原文与问题通过 JSON 放入单条 user 消息，明确视为不可信数据。没有工具、外部检索、第二次纠错调用或自动付费重试。

## 费用、限制和恢复

- 提问使用独立次数额度：账号滚动 **5小时5次、72小时15次**，IP滚动 **5小时5次**，全站提问按上海自然日 **40次**。整理仍为账号5小时5次/72小时20次、IP5小时5次、全站每日50次，两类次数互不占用；全站约3元/日费用预算继续共用。实际调用模型的失败计一次；输入拒绝、验证码、缓存及同请求ID重放不重复计数。
- 不另设独立资金池；兼容字段 `remainingQuestions` 表示账号独立提问滚动额度当前余量（最多5），同时取五小时与72小时的较小余量；不代表自然日次数，也不承诺网络/全站额度或费用预算仍可用。
- 整理与问答共用服务互斥、账号3分钟频率限制、网络频率限制与验证码。模型发送前先持久化完整负载的保守费用预留；有有效 usage 后按既有估价结算，无 usage 时保留预留。
- 第3次高频操作仍可返回 `428 VERIFICATION_REQUIRED`，`challenge` 与整理接口相同。用同一请求体和 `X-Campus-Proof: {"token":"…","answer":"1234"}` 提交。验证不会免除日限额/总预算。
- 相同账号、相同 `requestId`、相同原文和问题只发送一次模型请求。成功和安全失败结果持久化在现有 `sync.sqlite` 的 `notice_questions` 表；只保存输入哈希、请求编号和结果，不保存完整问题输入。不同账号隔离。
- 客户端断开后，已接纳请求继续完成；不自动发新请求。需要恢复时显式使用同一编号查询。成功重查返回当前滚动窗口的账号提问余量，不重复扣费。修改问题或原文需新编号。
- 服务重启时，未完成的编号标为中断；同编号不重发。可避免“可能已收费”请求被再次收费，但这种中断的答案可能无法恢复。
- 账本不自动删除，最多100000条后拒绝新问答。每日次数上限限制增长；维持有界磁盘占用和已收费编号记忆。账本随现有SQLite业务备份保留。
- 单实例服务把两类次数与金额预留原子写入同一个私密 `usage.json`；同实例并发不能超出最后一次余量。重启不清空，账号/IP只有带密钥哈希与时间戳。旧版共享记录没有可靠的用途信息，升级时保守地把已知记录一次计入两类，日计数到上海午夜重置，滚动记录按原时间逐条到期；不能重建旧版已经丢失的历史，也不把迁移当成新额度。此文件不支持多个后端进程同时写入。

| 状态/代码 | 客户端处理 |
| --- | --- |
| 401 `AUTH_REQUIRED` | 先登录 |
| 400/413/415 | 修正输入长度、字段或JSON类型；未调用模型 |
| 428 `VERIFICATION_REQUIRED` | 完成图片验证码，以原编号提交 |
| 400 `CAPTCHA_INCORRECT` / `INVALID_PROOF` | 沿用整理验证码提示 |
| 409 `QUESTION_IN_PROGRESS` | 仍在处理；按 `retryAfterSeconds` 后由用户显式查询同编号 |
| 409 `REQUEST_ID_CONFLICT` | 同编号内容变了；拒绝，不收费 |
| 429 `ACCOUNT_FIVE_HOUR_LIMIT` / `ACCOUNT_THREE_DAY_LIMIT` / `IP_FIVE_HOUR_LIMIT` | 对应滚动额度用完，按 `Retry-After` 等待 |
| 429 `ACCOUNT_RATE_LIMIT` / `IP_RATE_LIMIT` | 遵循 `Retry-After` |
| 429 `SERVICE_BUSY` | 整理或问答占用互斥，稍后重试原编号 |
| 429 `DAILY_COST_LIMIT` / `QUESTION_DAILY_LIMIT` | 共用费用预算或全站提问日次数上限 |
| 502 `AI_FORMAT_INVALID` / `AI_INCOMPLETE` / `AI_TIMEOUT` / `QUESTION_FAILED` | 已接纳失败，同编号只重放失败，不发模型 |
| 503 `QUESTION_INTERRUPTED` | 结果未知或重启中断，同编号不重新收费 |
| 503 `SERVICE_UNAVAILABLE` | 门禁/记录暂不可用；仅显式查询原编号 |
| 507 | 问答账本容量已满，联系维护者 |

所有响应 `no-store`；模型原始输出、请求内容、供应商密钥和验证器内部路径不会进入错误信息。HTTP响应丢失不等于请求未收费。客户端应保存最后一次问题与编号，成功/失败可恢复，禁止自动生成新编号重试。

首次启用（2.16已完成）除既有源码发布，还需同步 `server/nginx-https.conf` 中精确的 `/notice-question` 路由；只更新源码不会让旧代理自动放行新路径。
