# 服务器容量与后续规划

## 当前只读观测

以下是本轮获得的单次服务器观测值，时间为 2026-10-06。它们用于决定初始资源预算，不是压测、并发承诺或长期平均值。

| 项目 | 观测 |
| --- | --- |
| 配置 | 2 核；用户购买规格为 2 GB。 |
| 系统可见内存 | MemTotal 约 1,613 MB；MemAvailable 约 683 MB。预算以系统当前可见值为准。 |
| Swap | 1,024 MB，观测时未使用。 |
| 磁盘 | 总计约 40 GB，已用约 15 GB，可用约 24 GB。 |
| 系统负载 | 约 0.06。 |
| QQ 相关进程 RSS | 约 113 MB。 |
| Python 相关进程 RSS | 约 211 MB。 |
| 宝塔相关进程 RSS | 约 51 MB。 |
| 当前 Node 后端 RSS | 约 28 MB。 |
| 带宽 | 用户截图显示 3 Mbps 固定带宽；不是本轮带宽测速。 |

RSS 不等于项目能永久独占的内存；系统、其他服务和缓存还会占用资源。不能把 683 MB 可用内存全部分配给新功能，也不应把 swap 当正常运行内存。

## 当前产品为什么较轻

网页由 GitHub Pages 托管，网页与 APK 在 GitHub Actions 构建；不在这台小服务器上安装庞大的前端/Android 工具链。AI 计算在 DeepSeek 执行，阿里云只负责转发、JSON 合同校验、限频和计量。

后端保持一个实例和一次模型并发，成功结果最多在内存缓存 50 条、15 分钟；用量文件只保留必要计数。新版新增邀请码账号和文字同步，采用 Node 24 内置 SQLite 的两个本地文件，不增加常驻数据库进程。附件仍不上传服务器。

新版 systemd 配置给 API 256 MB 内存上限；可选 compose 给同样 256 MB 上限及 0.5 核预算。这是保护其他服务的上限，之前 Node 观测约 28 MB，不代表新增账号与同步后的实际峰值，更不意味着启动就预占 256 MB。密码派生异步执行，每次最多 16 MB、最多 4 个并发；超过时请求稍后再试，不建立无界队列。

## QQBot 与同步的余量

先为新增或扩展 QQBot 预留约 128–256 MB 的规划空间，再观察实际占用。已有 QQ 相关进程不等于未来 Bot 一定就是 113 MB：Node SDK、Python SDK 或需要桌面客户端的方式差异很大，选择登录方式和消息通道后再测量。

不在后端运行本地大模型、完整 Android 构建或大文件 OCR。未来 Bot 作为独立模块或进程接入通知文本队列，复用同一个 AI 服务与付费计量，不复制一套绕过全站限额的模型调用逻辑。是否自动读取群聊、保存或分发消息应由用户另行明确选择，本轮仅做架构预留。

用户已批准真实文字同步。每个邀请码账号具有独立空间，同步原文、整理结果、勾选与笔记；本地优先，离线不影响查看。单条上限 64 KiB，每账号最多 1,000 条现存通知、5 MiB 文字，最多 5,000 个包含删除记录的历史编号。全站最多 500 个账号、256 MiB 文字正文。实际 SQLite 文件还含索引、会话和 WAL，这些上限不是精确磁盘大小承诺。

每次同步最多 100 条变更和 1 MiB 请求，读取分页返回，避免一次加载全站或整个账号的大数据。相同通知的并发修改用版本比较发现冲突，删除保留记录避免旧设备复活内容。设备会话、账号和云记录不能只备份其中一个，搬家步骤见部署文档。更大规模需求出现前保持模块化单体；若以后上传附件，需先设总容量和备份方案，不默认开启。

## 带宽与磁盘比 CPU 更容易成为瓶颈

3 Mbps 的理论总速率约为 0.375 MB/s，实际通常更低。在理想情况下单个 5 MB 附件也需要约 13 秒，多个设备会分享带宽；这个换算不能当作实际下载速度承诺。

文字 JSON 远小于附件，当前阶段没有必要为文本通知同步升级服务器。先避免默认上传所有附件，以及在阿里云重复托管大体积 APK；安装包继续放 GitHub Release。

磁盘虽有约 24 GB 可用，也需要为系统更新、原有服务、日志和备份留空间。未来附件容量应使用明确的项目上限，通知数据库备份保存在服务器之外；不无限留存每次发布目录或日志。

## 何时才考虑升级

以下是运维观察信号，不是自动扩容规则，也不会自动产生付费资源：

- 日常操作开始频繁用 swap，或可用内存持续接近不足以容纳一个请求的水平。
- QQBot 与 API 相互影响，CPU 长时间繁忙而不是偶发峰值。
- 同时下载附件明显拖慢通知整理，或公网响应持续变差。
- 磁盘可用空间持续降低，日志和备份清理后仍不足。

先测量并找出瓶颈，再决定是否限制附件、调整 Bot 运行方式或更换服务器。新代码通过持久化接口、独立 API 配置、受限发布清单和可选容器部署支持搬家；服务器将在 2027 年 3 月到期，迁移步骤见 [DEPLOYMENT.md](DEPLOYMENT.md)。
