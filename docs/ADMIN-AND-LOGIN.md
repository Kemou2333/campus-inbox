# 管理后台与登录防护

管理页面位于后端 `/admin`，页面本身只提供登录表。账号列表、数量、用量、任务及其内容均由服务器鉴权后读取，不依赖前端隐藏按钮。

部署配置：

- `ADMIN_USERNAMES=kemou`：仅授权已有的该账号。默认空名单关闭后台；启动时固定已有账号 UUID，启动后新注册的相似名称不会获权。
- `ADMIN_ORIGIN=https://123.57.30.129`：管理页面的准确 HTTPS origin，同时加入登录允许来源。
- `ADMIN_REVIEW_DAYS=30`：其他账号主动允许维护查阅的任务内容，在创建后 30 天内可读。范围 1–365 天。

后台只读，不提供删除账号、修改通知、重跑模型、发邀请码或更改权限功能。会话仅存在页面内存，退出或重载需重新登录；密码、会话密钥、密码散列、邮箱和原通知不会写入新的访问日志。页面使用独立 CSP nonce，禁止 iframe 和外部脚本，原文及结果以纯文本插入。

## 内容与统计边界

每次新建后台整理任务可传可选 `maintenanceReviewConsent: true`。缺省为 `false`，旧记录不追溯授权，同一请求编号的重送不会追溯改变许可。维护许可不影响 AI 整理、云端恢复和用户自己的阅读。

账号和任务列表只提供数量、时间、状态与用量，不读取原文或结果。打开详情后，服务器允许管理员查看自己账号的任务内容；其他账号必须满足主动许可及维护查阅期限。期限只限制维护可见性，**不删除任何用户通知、任务或笔记**。

结果是持久保存的初始结构化快照，用户后续编辑以普通通知同步空间为准。旧任务未记录逐条模型/缓存/Token 指标时显示未知，不能当作零次调用。每日费用是服务内部保守估算，不是供应商账单。管理员列表每页 50 个账号、20 条任务；每个管理员每分钟最多 60 次读取。

## 登录协议

`POST /auth/options` 返回 `imageCaptchaEnabled: true`。

`POST /auth/challenge`：

```json
{"purpose":"login","clientId":"浏览器生成的随机 UUID"}
```

`purpose` 可为 `login`、`register`、`email`，回复 `id`、PNG `image`、`expiresAt`、`retryAfterSeconds`。图片不带答案文本。客户端编号须为 24–64 个字母、数字、下划线或短横线。

密码登录、邀请注册和邮件发验证码时附加：

```json
{"captcha":{"id":"服务返回的 id","answer":"四位数字"}}
```

验证码绑定准确的来源、IP 与用途，五分钟过期；一次成功即消费，五次猜错作废。只在独立测试中允许显式 `imageCaptcha:false`，生产入口没有关闭验证码的环境开关。

刷新限制：客户端六秒冷却、每分钟十次；共享校园 IP 每分钟六十次、每小时三百次。限制计数持久保存；更换客户端编号不能绕过 IP 限制。

密码尝试限制：每个 IP 每分钟十次／每小时一百次，每个账号每分钟五次／每小时二十次，邮件与用户名别名共享账号预算。滚动窗口防止卡整分钟边界集中尝试，限制计数在密码派生前提交。未解出图形验证码的请求只计网络次数，不耗尽被点名账号的密码预算，以免轻易锁住他人。未知账号与密码错误回复相同；限制不会永久锁住账号。既有邮件发送、代码验证、邀请码及 AI 额度限制继续生效。

只有本机反向代理提供的单个合法 `X-Real-IP` 才作为客户 IP；公网直接传该头、列表或非法地址不会获信任。反向代理应监听 HTTPS，将 `/admin` 转到本机后端；后端默认仅监听 `127.0.0.1`。

错误代码：`AUTH_CAPTCHA_REQUIRED`、`AUTH_CAPTCHA_INVALID`、`AUTH_CAPTCHA_RATE_LIMIT`、`AUTH_RATE_LIMIT`。限制响应携带 `retryAfterSeconds`，客户端应显示等待且不自动反复请求验证码。
