# 通知时间：明确多少，就记录多少

时间文字始终保留。只有原文明写的年、月、日、时、分才能用于完整时间；缺少的信息不会用当前日期、录入时间、年级或其他通知补齐。相对日期也不会把录入日期当成通知发布日期。

在原有第 4 版结果上增加两个可选字段：通知的 `deadlineSpec`、事项和时间节点的 `timeSpec`。旧结果、旧备份仍能读取，也不会为了兼容而给旧记录添加空字段。

```json
{
  "type": "partial",
  "year": null,
  "month": 10,
  "day": 7,
  "hour": 17,
  "minute": 0,
  "rawText": "10月7号17:00前"
}
```

每个结构都有上述七个字段。数字字段为原文明示的整数或 `null`；`rawText` 与它对应的 `deadlineText` 或 `timeText` 相同。不增加置信度。

| type | 意思 | 使用边界 |
| --- | --- | --- |
| `date_time` | 完整年月日和钟点 | 可换算完整时间；没有明写时区就不增加时区 |
| `date` | 完整年月日，没有钟点 | 可建议整天日历事项；不虚构 23:59 的截止 |
| `partial` | 只有部分明确分量 | 例如缺年份，需确认后才能加入准确日历或按完整截止排序 |
| `relative` | 今天、明天、周五等 | 保留文字；没有可信发布日期时不换算绝对日期 |
| `unknown` | 区间、重复安排或复杂表述 | 保留完整文字，数字字段为空；不随意选一个节点 |

`10月7号17:00前` 的年为空。`2026级新生` 不能给它补成 2026 年。`明天中午前` 不变成明天 12:00。原文写 `2026年10月20日24:00` 时，结构仍记录 20 日、24:00；完整 ISO 时间换算为 `2026-10-21T00:00:00`。

AI 负责选择本事项对应的时间文字和结构。后端再检查分量是否能在该时间文字及其所属原通知中得到证实。年份不会从旁边的标题、学年或其他日期借来。不能证实时仅保留文字，不让一条推测变成已确认的日程。

`deadlineSpec` 表示行动截止，事项 `timeSpec` 表示该行动对应的时间，时间节点 `timeSpec` 表示原文明示的活动或处理节点。活动开始、预计入账等时间不能自动变成学生的截止事项。该层不合并通知、不把已有通知重新发给 AI，也不自动写入手机日历。

确定性时间模块接受常见数字日期、中文月日、完整日期、明确钟点和 24:00。无法可靠分解的复杂表述走保守回退，原文仍可查看。完整时间的现有 ISO 字段与原来的备份版本保持兼容。
